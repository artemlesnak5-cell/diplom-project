# Дипломный проект: интернет-магазин часов Tissot

Тема: «Разработка интернет-магазина товаров класса люкс (на примере Tissot)».
Подготовлено к предзащите 15 октября 2026 года.

## Что работает

- Главная, каталог, поиск по названию/артикулу/цвету, фильтр по коллекции, сортировка.
- Отдельная страница каждого товара и фотографии.
- Регистрация, вход, выход через стандартную систему Django.
- Корзина в сессии: добавление, изменение количества, удаление, подсчёт стоимости.
- Оформление заказа с проверкой полей и остатка.
- Личный кабинет со списком собственных заказов и текущим статусом.
- Админка: товары, коллекции, цены, остатки, фото и изменение статуса заказа.
- Шесть демонстрационных моделей по 20 000 ₽. Первоначальный остаток — по 5 штук, это учебные данные.

**Фактически проверенная база: SQLite.** Настройки и миграции подготовлены для MySQL, но подключение к MySQL не проверялось: нет учётных данных сервера. Не утверждайте на защите, что работа с MySQL уже протестирована.

## Быстрый запуск на этом компьютере

Откройте `START_SITE.cmd` двойным щелчком. Оставьте окно работающим.

- Магазин: http://127.0.0.1:8000/
- Каталог: http://127.0.0.1:8000/catalog/
- Регистрация: http://127.0.0.1:8000/accounts/register/
- Заказы: http://127.0.0.1:8000/account/orders/
- Админка: http://127.0.0.1:8000/admin/

Локальные данные администратора — в `DEMO_ACCESS.txt`. Если файл потерян, задайте новый пароль командой `python manage.py changepassword demo_admin`.
Для покупателя зарегистрируйте отдельный аккаунт через сайт. Статус изменяйте из админки в другом браузере или приватном окне, чтобы не путать сессии.

## Установка на другом компьютере

Нужен Python 3.12 или 3.13. Распакуйте архив, откройте терминал в папке с `manage.py`:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_demo
.\.venv\Scripts\python.exe manage.py create_demo_admin
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Активация окружения не обязательна: команды используют его Python напрямую.
Если команда `python` не найдена, попробуйте `py -3`. После установки можно пользоваться `START_SITE.cmd`.
Архив не включает базу, личные заказы, аккаунты или пароли. Команды создают чистую базу и каталог. Повторный `seed_demo` не сбрасывает остатки и цены.

## Подключение MySQL

Это отдельный необязательный этап для текущей демонстрации. Нужен MySQL 8.0.11+ и доступ к администратору сервера. Не сбрасывайте пароль существующего сервера и не удаляйте чужие базы. Если доступа нет, попросите преподавателя или владельца компьютера создать отдельную учебную базу.

1. В MySQL Workbench подключитесь к серверу с известными владельцу логином и паролем.
2. Откройте вкладку SQL. Выполните следующие команды, заменив строку `REPLACE_WITH_YOUR_PASSWORD` собственным паролем нового пользователя. Это пример, а не реальный пароль:

```sql
CREATE DATABASE tissot_diploma CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'tissot_app'@'localhost' IDENTIFIED BY 'REPLACE_WITH_YOUR_PASSWORD';
GRANT ALL PRIVILEGES ON tissot_diploma.* TO 'tissot_app'@'localhost';
```

Если база или пользователь уже существуют, не удаляйте их — уточните у владельца, предназначены ли они для этого проекта.

3. Установите драйвер в окружение проекта:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-mysql.txt
Copy-Item .env.example .env
```

4. Откройте `.env` в редакторе и задайте:

```ini
DB_ENGINE=mysql
DB_NAME=tissot_diploma
DB_USER=tissot_app
DB_PASSWORD=ваш_пароль_нового_пользователя
DB_HOST=localhost
DB_PORT=3306
DJANGO_DEBUG=1
DJANGO_ALLOWED_HOSTS=127.0.0.1,localhost
```

5. Выполните `migrate`, `seed_demo`, `create_demo_admin` командами выше и запустите сайт. Смена настройки базы не переносит старые аккаунты и заказы из SQLite. Для предзащиты проще заполнить чистую базу демонстрационными товарами.
6. В Workbench убедитесь, что созданы таблицы `shop_product`, `shop_order`, `shop_orderitem`, `shop_category`, `auth_user`. Оформите учебный заказ и проверьте, что запись появилась именно в MySQL.

Ошибка `Access denied` означает неверные реквизиты или права. Ошибка `Can't connect` означает, что сервер/порт недоступен. Ошибка `No module named MySQLdb` означает, что драйвер не установлен в используемый Python.

## Структура

```text
config/settings.py       настройки Django, SQLite/MySQL, шаблоны, статика
config/urls.py           главный список адресов
shop/models.py          таблицы: Category, Product, Order, OrderItem
shop/views.py           обработка запросов браузера
shop/urls.py            адреса страниц магазина
shop/forms.py          валидация регистрации, количества и заказа
shop/cart.py           получение товаров корзины и расчёт цены
shop/services.py       транзакция создания заказа и списания остатка
shop/admin.py          интерфейс администратора
shop/migrations/       описание изменений структуры базы
shop/tests.py          автоматические проверки
templates/             HTML-шаблоны Django
static/                CSS и значок сайта
media/watches/          фотографии товаров
```

## Проверки

```powershell
python manage.py check
python manage.py test shop
```

На установленном Python 3.13.12 / Django 5.2.15 / SQLite выполнено 12 проверок: страницы и поиск, регистрация и хеширование пароля, POST/CSRF, валидация корзины, требование входа, полный заказ и повторная отправка, недостаток остатка, неизменность цены заказа и запрет чужого доступа, неверный токен, скрытые товары и пустая корзина, запрет админки покупателю, повторное заполнение каталога. Драйвер MySQL не нужен для SQLite.

## Границы проекта

Нет реального приёма платежей, почтовых уведомлений, расчёта доставки, восстановления пароля через почту, отслеживания посылок и истории переходов статуса. Статус — текущее значение, вручную заданное администратором; браузер показывает обновление после перезагрузки страницы. При создании заказа остаток уменьшается. Отмена и автоматический возврат остатка не реализованы.

Это локальная учебная версия, а не готовый к эксплуатации публичный магазин. Для публикации нужны Python-хостинг, HTTPS, уникальный секрет, DEBUG=0, настройка ALLOWED_HOSTS, выдача статики и медиа, резервные копии и защита от перебора паролей. Простая загрузка в Netlify Drop, использованная для HTML-версии, этот Django-сервер не запускает.
